# 활용 사례

Grimoire 를 실제로 어떻게 쓰고 있는지 모은 문서다. 기능 설명은 [README](../README.md) 에 있고, 여기서는 "어떤 문제를 어떻게 풀었나"만 다룬다.

사례는 직군·업무 형태 수준으로만 적는다. 회사명, 사내 시스템 이름, 개인 식별 정보는 넣지 않는다.

> 직접 써 보셨다면 [사용 후기](#사용-후기-남기기)를 남겨 주세요. 좋은 후기는 동의를 받아 이 문서에 사례로 옮겨 싣습니다.

```mermaid
flowchart LR
    Src["흩어진 기록<br/>(메신저·업무 로그·학습 메모)"] -->|"마크다운으로 정착"| KB[("마크다운 KB")]
    KB -->|"search / get_runbook / get_context"| Claude["Claude Code"]
    Claude -->|"write_note"| KB
    Claude --> Out["산출물<br/>(보고·블로그·배포 작업)"]
```

---

## 1. 메신저 검색의 한계를 KB 로 메우기 — PO 업무 반자동화

**누가**: 여러 팀의 요청을 받아 정리하는 PO(제품 책임자)

**문제**: 업무 메신저의 검색이 약해, 지난 논의나 결정 사항을 다시 찾는 데 시간이 많이 들었다. 요청 접수·정리 같은 반복 업무도 매번 손으로 했다.

**방법**
- 메신저 대화를 주기적으로 마크다운으로 백업해 KB 아래에 둔다.
- 요청 정리·현황 공유 같은 PO 업무 흐름은 Grimoire 로 과거 맥락을 끌어오게 해서 반자동으로 돌린다.

**효과**: "그때 뭐라고 했더라"를 메신저 앱이 아니라 KB 에서 찾는다. 반복 업무의 초안은 Claude 가 맥락을 채운 상태로 시작한다.

## 2. 쌓인 노트를 블로그 글로 — 기록에서 발행까지

**누가**: 같은 PO 사용자, 그리고 작성자 본인

**문제**: 업무 중에 정리한 메모는 많은데, 글 한 편으로 묶어 내는 데까지 가지 못했다.

**방법**
- `search` 와 `links` 로 한 주제에 걸친 노트를 모아 초안 재료로 쓴다.
- 블로그 디렉토리를 `redact:true` 로 지정해 두면, 사내 식별자가 섞인 초안은 `write_note` 가 저장을 거부한다. 공개 글에 내부 정보가 새는 사고를 저장 단계에서 막는다.

**효과**: 쌓아 둔 기록이 소재가 되어 글을 꾸준히 하나씩 내고 있다.

## 3. 반복 절차는 런북으로 한 번만 — 배포·클러스터 작업

**누가**: 작성자 (백엔드·DevOps)

**문제**: 배포 절차, 클러스터 접속 방법, 점검 순서를 세션마다 Claude 에게 다시 설명했다.

**방법**
- 절차를 `type:runbook` 노트로 한 번 써 둔다.
- 이후 작업 디렉토리에서 세션을 열면 `SessionStart` 훅이 관련 런북을 자동으로 주입하고, Claude 는 `get_runbook` 으로 절차를 확인한 뒤 작업한다.
- 수동 배포 후 변경 범위를 정리해 검증·공지하는 흐름도 런북을 기준으로 돌린다.

**효과**: 설명을 반복하지 않는다. 절차가 바뀌면 런북 한 곳만 고치면 된다.

## 4. 매일의 기록이 주간 회고로 — 업무 로그 누적

**누가**: 작성자

**방법**
- 매일 업무 로그를 KB 의 날짜별 경로에 남긴다. 전날 계획을 기준으로 이어 쓴다.
- 주 단위로 그 로그를 모아 회고를 만든다. 경로와 frontmatter 규약이 일정해서 집계가 쉽다.

**효과**: 데일리 보고와 주간 회고를 따로 쓰지 않는다. 한 번 쓴 기록이 두 산출물이 된다.

## 5. 학습을 같은 틀로 — 학습노트 스캐폴딩

**누가**: 작성자

**방법**: `new_study` 로 강의·책·AI 대화·공식 문서마다 같은 모양의 학습 공간을 만든다. 요약(`notes/`)과 직접 판 심화(`deep-dive/`)를 나누고, AI 대화로 공부한 내용은 출처 확인 표로 검증 여부를 남긴다.

**효과**: 노트마다 형식이 제각각이 되지 않아, 나중에 검색으로 다시 찾을 수 있다.

## 6. 내 생각과 일하는 방식을 KB 에 쌓기 — 세션 회고로 스타일 기록

**누가**: PO·PM·기획 역할 사용자 (사용 1주 ~ 1개월, [사용 후기](https://github.com/alanhakhyeonsong/grimoire/discussions/1)에서 옮김)

**문제**: 자기 생각과 업무 철학을 한 번에 다 정의할 수 없어서, 반복 업무를 맡길 때마다 기준을 처음부터 다시 설명해야 했다.

**방법**
- AI 에이전트와 세션을 끝낼 때마다 "여기서 대화한 나의 생각과 패턴을 md 로 정리해 Grimoire 에 넘겨" 라고 요청해, 일하는 스타일을 조금씩 쌓는다.
- 반복 업무는 파이프라인으로 만들고, 그 업무를 수행할 정책과 흐름은 마크다운으로 정의해 둔다.
- 역할별 지침서를 써서 스스로 읽고 기준으로 삼는 동시에 KB 에도 넣는다. 에이전트가 같은 지침을 참고하므로 결과물 품질의 하한이 올라간다.
- 접근할 수 있는 업무 공간의 자료는 읽어 와 KB(마크다운)로 저장하고, 검토나 히스토리 확인에 쓴다.
- 이 흐름을 로컬 웹 UI 기반 올인원 도구로 묶어 쓴다. 이 도구는 Grimoire 가 제공하는 것이 아니고 사용자가 직접 구성했다.

**효과**: 업무 스트레스가 줄었다. 매번 기준을 설명하지 않아도 쌓아 둔 생각과 정책을 바탕으로 에이전트가 초안을 먼저 잡아 준다.
